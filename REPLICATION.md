# Replication guide

This is the replication package for *Exact Mutation Adequacy for Access-Control Policies Is a
Property of Guards, Not of a Language* (Hassan, Alraas, Rezki, Alameri, Sadek and AbuSerrieh;
submitted to *The Journal of Systems and Software*). The repository's front page,
[`.github/README.md`](.github/README.md), gives the overview and the data availability
statement. This file covers each step in detail. The `README.md` at the root is the
TrustWeave tool's own README. It is left as it was, because the tool's tests read it.

## Checking the snapshot

The paper cites commit `a5beb63033a3722a4051bd68241f25e010b0bace` of
<https://github.com/MohammadThabetHassan/trustweave>. That commit and its full history are
here unchanged. A git commit hash is computed from its content, so a commit with this hash
has the same files as the upstream commit with the same hash.

The packaging commits after it are listed by:

```bash
git diff --name-status a5beb630 HEAD
```

They add `.github/README.md`, `REPLICATION.md`, `CLAIMS.md` and `replication/`. They
rewrite `.zenodo.json` to describe this package and list the authors in the paper's order,
and they remove `.github/dependabot.yml` so that the frozen package gets no dependency-update
pull requests. They change no code, artifact or protocol. GitHub Actions
are turned off for this repository. The workflow files are kept as they were upstream.

## Environment

- **Python 3.11 or newer**, then `pip install -e ".[dev]"` from the repository root. This is
  enough for the checks that read only the artifacts.
- **Docker**, for everything else. `reproduce/Dockerfile` pins the base image by digest and
  installs OPA 1.20.2, the Kyverno CLI 1.19.1, the Cedar CLI 4.12.0 (experimental build),
  cvc5 1.3.1, `cedarpy` 4.12.1 and a JDK. It checks each downloaded binary against the
  SHA-256 its release publishes. See [`reproduce/README.md`](reproduce/README.md#the-image).
- **Lean 4** through `elan` for `proofs/lean/`. The toolchain (`leanprover/lean4:v4.34.1`) and
  Mathlib are pinned in `lean-toolchain` and `lake-manifest.json`.

## Reproducing, from minutes to hours

Commands are run from the repository root. `reproduce/run.sh` is the container's entry point.

| Step | Command | Network | Time |
|---|---|---|---|
| Check the manuscript against the artifacts | `TRUSTWEAVE_PAPER=/path/to/main.tex python scripts/check_manuscript.py` | none | seconds |
| Tool versions, pre-registrations, the study scripts' tests, the solver check of the witness construction | `docker run --rm trustweave-reproduce verify` | none | minutes |
| Recompute an artifact that needs only other artifacts | the commands under *From the artifacts alone* in [`reproduce/README.md`](reproduce/README.md#each-artifact-and-the-command-that-writes-it) | none | seconds each |
| Fetch the corpora at the commits the artifacts record | `docker run --rm -v "$PWD/corpora:/corpora" trustweave-reproduce corpora` | yes, about 1 GB | minutes |
| Re-measure every corpus and diff the counts | `docker run --rm -v "$PWD/corpora:/corpora" trustweave-reproduce membership` | none after the step above | about an hour |
| Re-run SymCC's check of the Cedar verdicts | `docker run --rm trustweave-reproduce symcc` | once | under an hour on eight cores |
| Re-run the comparison with Xu et al.'s criteria | `docker run --rm trustweave-reproduce xacml` | once | well under an hour |
| Re-run a study on real policy | the commands under *Studies on real policy* in [`reproduce/README.md`](reproduce/README.md#each-artifact-and-the-command-that-writes-it) | varies | up to hours each |
| Build the Lean development | copy `proofs/lean/` out of the checkout, then `lake exe cache get && lake build` there ([`proofs/lean/README.md`](proofs/lean/README.md#building) says why) | once, for Mathlib | minutes with the cache |

`check_manuscript.py` needs the manuscript source with `supplement.tex` and `refs.bib` beside
it. The manuscript is not in this repository (see the front page). Without it the script
reports that it has nothing to check and exits 0.

## Finding the source of a number

[`CLAIMS.md`](CLAIMS.md) lists the artifacts behind the pinned figures for each table, figure
and section of the paper, and how each artifact is written. [`replication/claims.csv`](replication/claims.csv)
has one row per printed figure: where it is printed, what it is, the value the artifact
gives, and the artifacts it depends on.

Both files are generated by `replication/claims_map.py` from the pins in
`scripts/check_manuscript.py`. The script finds each artifact a pin depends on by changing
that artifact's contents and seeing whether the value the pin demands changes. To regenerate
them after a revision, run it against the manuscript with its `.aux` files beside it. The run
takes about six minutes:

```bash
python replication/claims_map.py --paper /path/to/main.tex
```

## Pre-registration

Each pre-registered study's script records the SHA-256 of its protocol (`docs/*PROTOCOL*.md`)
in the artifact it writes, and it refuses to run if the protocol file hashes to anything else.
`python scripts/check_protocols.py` checks that every recorded hash belongs to a protocol in
this repository. As the paper says, these hashes were recorded by the authors and no outside
registry timestamped them. The commit history is here for anyone who wants to inspect it.

## What does not reproduce exactly

[`reproduce/README.md`](reproduce/README.md#what-does-not-reproduce-exactly-and-why) lists
each case and its reason. In summary:

- The third-party samples were drawn with GitHub code search, which returns different results
  over time. The draw cannot be repeated, but every measurement on the sample can, because
  the manifests pin every file.
- The history file behind `cedar-real-edits-v1` was not kept. The artifact records both
  versions of every pair it measured.
- Solver time limits depend on the machine. A fresh SymCC run may count a different number of
  "no answer" results, though its verdicts should not differ. MC/DC rows in the XACML
  comparison may also change on a faster machine.
- A few artifacts record a field imprecisely, for example an engine name written twice. Each
  is listed there with the value that was actually used.
